# yt.sh output

Each command prints plain text, so an agent without the dependencies can write the same output by hand.

## search

One line per hit, at most 8, fields split by a pipe with a space on each side:

```text
<11-char id> | <title> | <channel> | <duration m:ss or h:mm:ss>
```

## channel

One line per upload, newest first, at most `n`:

```text
<11-char id> | <title> | <duration>
```

## fetch

Writes `<out_dir>/<id>.txt` (`out_dir` defaults to a new temp dir) and prints `<path> (<count> caption lines)`. The file holds a header, one blank line, the video's description with each line quoted by `> `, one blank line, then one line per caption:

```text
# <title>
# <channel> | <upload date YYYYMMDD> | <duration> | <channel URL>
# <the video's watch-page URL>

> <description line, with its links>
>
> <description line>

# captions: <auto-generated | manual>
[m:ss] <caption text, whitespace collapsed to single spaces>
```

A video with no description has no `>` lines. When the metadata lookup fails, the header is the single line `# <id>` and there is no description. Minutes keep counting past 59, so a caption at one hour five minutes reads `[65:00]`.

## save

Fetches as above, then writes `<notes_dir>/<title>.md` (characters file systems refuse are dropped from the title) and prints `<path> (<count> caption lines)`. Each save also rebuilds `<notes_dir>/index.md`: one table row per note (saved date, linked title, channel, length), newest save first, read from the notes' properties. When a note in `notes_dir` already has the video's `watch?v=<id>` URL as its `source`, it prints `<that path> (already saved)` and fetches nothing. The note:

````text
---
source: <watch-page URL>
channel: <channel>
published: <YYYY-MM-DD>
duration: "<duration>"
saved: <today YYYY-MM-DD>
captions: <auto-generated | manual>
tags: [youtube]
---

# <title>

## Description

<description, unquoted; each chapter line such as `0:00 Intro` or `(0:18) - Rule` gets a `1. ` prefix so it renders as an ordered list and its time links to that moment (`[0:00](https://youtu.be/<id>?t=0)`), a plain line followed by another plain line ends in `\` so each shows on its own line, and a blank line separates a list from plain text and surrounds a separator line such as `--------`>

- Youtube: <channel URL>

## Transcript

[m:ss](https://youtu.be/<id>?t=<seconds>) <the whole sentences that start in that minute, joined; m:ss is when the first one starts, linked to that moment>

[m:ss](...) ...
````

## text

`yt.sh text <note|fetch file>` prints every caption joined into one paragraph per minute, each opening with the exact time its first sentence starts, with a blank line between. A saved note already holds this, so for a note it prints the transcript section as is:

```text
[0:00](https://youtu.be/<id>?t=0) <sentences that start in minute 0>

[1:02](https://youtu.be/<id>?t=62) <sentences that start in minute 1>
```

## link

`yt.sh link <note> "<phrase>" <url> <author|found>` wraps the first mention of `<phrase>` in the note's transcript that is not already inside a link, as `[<phrase>](<url> "<author|found>")`, and prints `linked '<phrase>' (<kind>)`. It never adds or changes words. `author` means the URL came from the video's description; `found` means a web search found it. Exit `1` with the reason on stderr when the phrase has no unlinked mention, the URL is not `http(s)`, or the kind is neither.

## Exit codes

- `0`: success.
- `2`: unknown command; usage goes to stderr.
- `3`: a dependency is missing and the one-time venv install failed; stderr names it.
- `4`: no transcript (no captions, unavailable video or a blocked request); stderr gives the reason in one line and no file is left behind.
- Any other non-zero code comes from yt-dlp.

## By hand

Open the video page, choose "Show transcript" under the description, and copy the lines into the same `[m:ss] text` shape under the header above.
